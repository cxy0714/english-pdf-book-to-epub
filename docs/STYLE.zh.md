# 译稿风格约定（注入翻译提示词）

本文件会被 `tools/bookkit/mt.py` 读入并附加到系统提示词末尾，是**唯一**的译文风格来源：
要改译文风格，改这里，不要改代码里的提示词。

## 1. 总则

- 学术书面语。原文是严谨的论证性散文，译文应保持同样的密度与语气，不口语化、不解释化。
- 忠实优先于流畅。原文有歧义时保留歧义，不要"替作者说清楚"。
- 不增删内容。不加译注、不加"译者按"、不合并段落、不拆分段落。
- 句长随原文。原文本就用长句推进论证，不必强行拆成短句；但中文忌堆叠"的"字，可适度调整定语顺序。

## 2. 术语

- 术语表（`books/<slug>/glossary.json`）里的定译优先，全文一致。
- 术语表没有的专有名词：机构名、机制名、法案名、软件名保留英文（如 simultaneous ascending auction 若已成术语则用定译；FCC、PCS 一律保留英文）。
- 人名按术语表音译；术语表未收的人名，首次出现用「中文（English）」，之后用中文。
- 经济学既有译名从众：mechanism design = 机制设计，revelation principle = 显示原理，winner's curse = 赢家诅咒，envelope theorem = 包络定理。

## 3. 数学与符号

- 公式、变量、函数名、希腊字母、集合与运算符一律照抄，不翻译、不改成中文符号。
- `$…$` 与 `$$…$$` 内的内容原样保留。
- 占位符 `[[fn1]]`（脚注角标）、`[[m2]]`（行内公式）、`[[img3]]`（图片）原样保留、位置不变。
- 数字、单位、年份、页码照抄；英文中的千分位逗号保留（如 2,371,000）。
- 数学表达式里的英文说明（如 `max`、`arg max`、`s.t.`）保留英文。

## 4. 标记与结构

- 标题保留编号：`2.3 Simultaneous Ascending Auctions` → `2.3 同步升价拍卖`。
- 脚注条目开头保持 `[^n]`，其后为译文。
- 列表项、图题、来源注（Source: …）与正文同等对待，正常翻译。
- 参考文献条目、索引条目、表格行不翻译（流水线会跳过，不要在译文里补写）。

## 5. 用词偏好（本书）

- auction = 拍卖；bidder = 竞买人（首次出现可用「竞买人（bidder）」），不用"投标人"（易与招投标混淆）。
- seller = 卖家；buyer = 买家；auctioneer = 拍卖人。
- payoff = 收益；surplus = 剩余；welfare = 福利；revenue = （卖家的）收益／收入。
- efficient = 有效的（配置语境）；不要译成"高效的"。
- "let …" 的祈使式定义句：译作「令…」；"suppose that" = 「假设」；"we assume" = 「我们假设」（保留第一人称）。
- "the auction" 泛指的定冠词不必每处都译"该"。
- 连接词：however = 然而；moreover = 而且；in contrast = 与之相对；nevertheless = 尽管如此。

## 6. 禁止项

- 不要输出英文原文与中文并列（双语对照由排版阶段完成，译文里不要重复英文段落）。
- 不要输出任何非译文内容：不写"以下是译文"、不加分隔线、不加代码块标记。
- 不要把表格行、公式块、图片行补进译文（它们不在待译条目里）。
